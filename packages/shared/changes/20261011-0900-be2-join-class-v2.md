# BE-2: join_class v2 in the api-client (additive, no change to packages/shared types)

Date: 2026-10-11 09:00 IST. Lane: BE-2. Nothing in `packages/shared/src` changed; this records the
`@paisa/api-client` surface added with `supabase/migrations/20261011090500_join_class_v2.sql`.
`JoinClassResult` is unchanged.

## joinClass(classCode, nickname, opts?)

`opts.lang?: Lang` is the language picked in onboarding. It is saved as the student's language; without
it, or with a value the server doesn't know, the student gets the class default. `default_lang` in the
result is still the class's. Calls with two arguments send exactly what they sent before.

## Errors

- New `ApiErrorCode` `class_closed`: `join_class`, HTTP 403. The facilitator closed the class to new
  joins. Not retryable.
- `ApiError` gains an optional 4th field, `suggestions?: string[]`, set only for `nickname_taken`: up
  to 3 free nicknames that pass the word filter. It may be `[]` (none found). It is `undefined` when
  the server sent no JSON array of strings; parsing never throws.
- `toApiError` also reads the PostgREST error's `details`.

## Classes (staff)

- `ClassRow` gains `join_open: boolean` (default `true`).
- `setJoinOpen(classId, open): Promise<void>`: `false` closes the class to new joins; students
  already in it keep playing. Throws `class_not_found` if no row was updated (not your class).
- `rotateClassCode(classId): Promise<string>`: a fresh code for a leaked one. The old code stops
  working for joins; students who already joined keep syncing. Anyone but the owning facilitator
  on the staff allowlist gets `class_not_found`.
